Tensor Core 是 NVIDIA GPU 上专为矩阵运算设计的硬件加速单元，而 WMMA（Warp Matrix Multiply-Accumulate）是 CUDA 提供的 C++ API，让开发者无需编写 PTX 汇编即可调用 Tensor Core 的算力。本文从零开始介绍 Tensor Core 的硬件原理和 WMMA API 的使用方法。

## 1. Tensor Core 是什么

### 1.1 直觉理解

普通的 CUDA Core 每个时钟周期执行一次浮点乘加（FMA）：$d = a \times b + c$，处理的是标量运算。而 Tensor Core 每个时钟周期完成一次**小矩阵**的乘加运算：

$$
D = A \times B + C
$$

这就像普通工人一次搬一块砖，而 Tensor Core 是一台叉车，一次搬一整托盘。单次操作的计算密度提升了一个数量级。

### 1.2 硬件规格

Tensor Core 从 Volta 架构（SM70）开始引入，每代都有增强：

| 架构 | 计算能力 | 每 SM Tensor Core 数量 | 原生支持精度 |
|------|---------|----------------------|-------------|
| Volta | SM70 | 64（第一代） | FP16 |
| Turing | SM75 | 64（第二代） | FP16, INT8, INT4 |
| Ampere | SM80 | 4（第三代） | FP16, BF16, TF32, INT8, INT4 |
| Hopper | SM90 | 4（第四代） | FP16, BF16, TF32, FP8, INT8 |

💡 **提示**：Ampere 将 Tensor Core 数量从 64 大幅缩减到 4，但每个第三代 Tensor Core 的吞吐量远超前代，总算力实际在增长。数量减少、单元更强是 NVIDIA 的设计趋势。

### 1.3 Tensor Core 的基本运算

以 Volta 第一代 Tensor Core 为例，每个 Tensor Core 执行的基本操作是一个 $4 \times 4 \times 4$ 的矩阵乘加：

$$
D\_{4 \times 4} = A\_{4 \times 4} \times B\_{4 \times 4} + C\_{4 \times 4}
$$

但在编程层面，我们不直接操作单个 Tensor Core。NVIDIA 提供了 Warp 级别的抽象——一个 Warp（32 线程）协作驱动多个 Tensor Core，完成更大分块（如 $16 \times 16 \times 16$）的矩阵乘加。这就是 WMMA API 的由来。

## 2. WMMA API 概览

### 2.1 编程模型

WMMA 的核心思想是：**一个 Warp 的 32 个线程协作完成一次矩阵乘加运算**。每个线程持有矩阵的一部分数据（称为 fragment），具体哪个线程持有哪些元素由硬件决定，对程序员透明。

编程流程分为三步：

📥 加载 → ⚙️ 计算 → 📤 存储

1. **Load**：将矩阵数据从内存加载到 fragment 中
2. **MMA**：调用矩阵乘加指令
3. **Store**：将结果从 fragment 写回内存

### 2.2 核心类型与函数

WMMA API 位于 `nvcuda::wmma` 命名空间，需要包含头文件：

```cpp
#include <mma.h>
using namespace nvcuda;
```

核心组件：

| 组件 | 作用 |
|------|------|
| `wmma::fragment<...>` | 矩阵分片，存储在寄存器中 |
| `wmma::load_matrix_sync()` | 从内存加载数据到 fragment |
| `wmma::store_matrix_sync()` | 将 fragment 写回内存 |
| `wmma::mma_sync()` | 执行矩阵乘加 $D = A \times B + C$ |
| `wmma::fill_fragment()` | 用常量填充 fragment |

### 2.3 Fragment 类型详解

`fragment` 是一个模板类，声明时需要指定角色、形状和数据类型：

```cpp
wmma::fragment<wmma::matrix_a, M, N, K, half, wmma::row_major> a_frag;
wmma::fragment<wmma::matrix_b, M, N, K, half, wmma::col_major> b_frag;
wmma::fragment<wmma::accumulator, M, N, K, float> c_frag;
```

模板参数含义：

- **角色**：`matrix_a`、`matrix_b` 或 `accumulator`，分别对应 $A$、$B$、$C/D$ 矩阵
- **M, N, K**：矩阵分块尺寸，$A$ 为 $M \times K$，$B$ 为 $K \times N$，$C/D$ 为 $M \times N$
- **数据类型**：输入矩阵通常为 `half`（FP16），累加器通常为 `float`（FP32）
- **布局**：`row_major` 或 `col_major`（仅 `matrix_a` 和 `matrix_b` 需要指定）

⚠️ **注意**：不是所有 M/N/K 组合都合法。常用的合法组合包括 16×16×16、32×8×16、8×32×16。

## 3. 第一个 WMMA 程序：矩阵乘法

### 3.1 完整示例

下面实现一个使用 Tensor Core 的矩阵乘法 Kernel，计算 $C = A \times B$，其中 $A$ 为 $M \times K$，$B$ 为 $K \times N$：

```cpp
#include <mma.h>
#include <cuda_fp16.h>

using namespace nvcuda;

const int WMMA_M = 16;
const int WMMA_N = 16;
const int WMMA_K = 16;

__global__ void wmma_gemm(half *A, half *B, float *C,
                          int M, int N, int K) {
    int warpM = (blockIdx.x * blockDim.x + threadIdx.x) / warpSize;
    int warpN = blockIdx.y;

    wmma::fragment<wmma::matrix_a, WMMA_M, WMMA_N, WMMA_K,
                   half, wmma::row_major> a_frag;
    wmma::fragment<wmma::matrix_b, WMMA_M, WMMA_N, WMMA_K,
                   half, wmma::col_major> b_frag;
    wmma::fragment<wmma::accumulator, WMMA_M, WMMA_N, WMMA_K,
                   float> c_frag;

    wmma::fill_fragment(c_frag, 0.0f);

    for (int k = 0; k < K; k += WMMA_K) {
        int aRow = warpM * WMMA_M;
        int aCol = k;
        int bRow = k;
        int bCol = warpN * WMMA_N;

        if (aRow < M && aCol < K && bRow < K && bCol < N) {
            wmma::load_matrix_sync(a_frag, A + aRow * K + aCol, K);
            wmma::load_matrix_sync(b_frag, B + bRow + bCol * K, K);
            wmma::mma_sync(c_frag, a_frag, b_frag, c_frag);
        }
    }

    int cRow = warpM * WMMA_M;
    int cCol = warpN * WMMA_N;
    if (cRow < M && cCol < N) {
        wmma::store_matrix_sync(C + cRow * N + cCol, c_frag, N,
                                wmma::mem_row_major);
    }
}
```

### 3.2 代码解析

**Warp 到矩阵分块的映射**：每个 Warp 负责输出矩阵 $C$ 中一个 $16 \times 16$ 的分块。`warpM` 和 `warpN` 确定该 Warp 负责的分块位置。

**K 维循环**：沿 K 维度迭代，每次加载 $A$ 的一个 $16 \times 16$ 列条和 $B$ 的一个 $16 \times 16$ 行条，累加到 `c_frag` 中。

**Leading Dimension 参数**：`load_matrix_sync` 的最后一个参数是 leading dimension（行主序时为列数，列主序时为行数），用于计算内存中相邻行/列的偏移。

### 3.3 启动配置

```cpp
// 每个 Block 包含若干 Warp，每个 Warp 处理一个 16x16 输出分块
dim3 block(128);  // 4 个 Warp
dim3 grid((M + WMMA_M - 1) / WMMA_M / (block.x / warpSize),
          (N + WMMA_N - 1) / WMMA_N);

wmma_gemm<<<grid, block>>>(d_A, d_B, d_C, M, N, K);
```

## 4. 数据布局与精度选择

### 4.1 支持的精度组合

WMMA API 支持多种输入/输出精度组合，不同架构支持范围不同：

| 输入类型 | 累加器类型 | 最低架构要求 |
|---------|-----------|-------------|
| `half` (FP16) | `float` (FP32) | SM70 (Volta) |
| `half` (FP16) | `half` (FP16) | SM70 (Volta) |
| `nv_bfloat16` (BF16) | `float` (FP32) | SM80 (Ampere) |
| `float` + `precision::tf32` | `float` (FP32) | SM80 (Ampere) |
| `int8_t` | `int32_t` | SM75 (Turing) |

💡 **提示**：TF32 模式下输入仍声明为 `float`，通过 `wmma::precision::tf32` 模板参数启用，硬件会自动截断尾数。实际工程中最常用的组合是 FP16 输入 + FP32 累加。FP16 累加虽然更快，但容易溢出，仅适合数值范围较小的场景。

### 4.2 行主序 vs 列主序

`load_matrix_sync` 要求你明确指定矩阵在内存中的存储布局：

- **行主序（row_major）**：同一行的元素在内存中连续
- **列主序（col_major）**：同一列的元素在内存中连续

```cpp
// A 按行主序存储：A[i][j] 位于地址 A + i * lda + j
wmma::load_matrix_sync(a_frag, ptr, lda);  // lda = 列数

// B 按列主序存储：B[i][j] 位于地址 B + j * ldb + i
wmma::load_matrix_sync(b_frag, ptr, ldb);  // ldb = 行数
```

⚠️ **注意**：布局声明必须与实际内存布局一致，否则计算结果会静默出错（不会报错），这是最常见的 WMMA 调试陷阱。

### 4.3 合法的 M/N/K 组合

不同架构支持的分块尺寸：

| 架构 | FP16 支持的 (M, N, K) |
|------|----------------------|
| SM70+ | 16×16×16, 32×8×16, 8×32×16 |
| SM75+ | 上述 + 更多 INT8 组合 |
| SM80+ | 上述 + 16×16×8 (TF32) |

选择建议：**16×16×16 是最通用的选择**，兼容性最好且性能稳定。32×8×16 和 8×32×16 适合输出矩阵形状极不对称的场景。

## 5. 性能对比与适用场景

### 5.1 Tensor Core vs CUDA Core 性能

以 A100 GPU（SXM）为例，理论峰值算力对比：

| 计算单元 | FP16 算力 | FP32 算力 |
|---------|-----------|-----------|
| CUDA Core | 78 TFLOPS | 19.5 TFLOPS |
| Tensor Core | 312 TFLOPS (FP16) | 156 TFLOPS (TF32) |

Tensor Core 的 FP16 峰值算力是 CUDA Core FP16 的约 **4 倍**，是 CUDA Core FP32 的 **16 倍**。但要达到 Tensor Core 峰值，需要满足：

1. 矩阵维度是分块尺寸的整数倍（避免边界浪费）
2. 数据在 Shared Memory 中对齐（避免 bank conflict）
3. 计算密度足够高（K 维度足够大，摊薄加载开销）

### 5.2 什么时候该用 Tensor Core

| ✅ 适合使用 | ❌ 不适合使用 |
|------------|-------------|
| 大矩阵乘法（GEMM） | 逐元素操作（如 ReLU） |
| 卷积运算（可转化为 GEMM） | 稀疏计算 |
| Attention 中的 QK^T 和 Score×V | 矩阵维度极小（< 16） |
| 批量小矩阵乘法 | 精度要求必须为 FP64 |

### 5.3 WMMA vs cuBLAS vs CUTLASS

在实际工程中，直接使用 WMMA API 编写高性能 GEMM 并不容易。各层抽象的定位：

| 方案 | 抽象层级 | 适用场景 |
|------|---------|---------|
| WMMA API | 低（Warp 级） | 学习原理、自定义融合 Kernel |
| CUTLASS | 中（模板库） | 需要定制但追求高性能 |
| cuBLAS | 高（黑盒库） | 标准 GEMM，开箱即用 |

📌 **关键点**：如果你的目标只是快速完成矩阵乘法，直接用 cuBLAS。WMMA 的价值在于：(1) 理解 Tensor Core 工作原理；(2) 在自定义 Kernel 中融合矩阵运算（如 FlashAttention 中将 GEMM 与 Softmax 融合）。

## 6. 常见陷阱与调试技巧

### 6.1 典型错误清单

| 问题 | 症状 | 解决方法 |
|------|------|---------|
| 布局声明与实际不匹配 | 结果数值错误 | 检查 row/col_major 与内存布局是否一致 |
| leading dimension 传错 | 结果错位或越界 | 行主序传列数，列主序传行数 |
| 非 Warp 对齐的线程调用 WMMA | 程序崩溃或未定义行为 | 确保只有完整 Warp 执行 WMMA 代码 |
| 矩阵维度不是分块的整数倍 | 边界越界读取 | 对边界分块做 padding 或条件判断 |
| 混用不同 fragment 的 M/N/K | 编译错误 | 所有 fragment 使用相同的 M/N/K 模板参数 |

### 6.2 调试建议

1. **先用小矩阵验证正确性**：用 $16 \times 16$ 的矩阵测试，手动计算期望结果对比
2. **打印 fragment 内容**：`fragment` 的 `.x` 数组可以直接访问（但元素到矩阵位置的映射是未定义的，仅用于调试）
3. **使用 compute-sanitizer 检测越界**：`compute-sanitizer --tool memcheck ./your_program`
4. **对比 cuBLAS 结果**：将 WMMA Kernel 的输出与 cuBLAS 的结果做 diff，快速定位数值问题

### 6.3 性能优化方向

当基础版本跑通后，可以从以下方向优化：

1. **使用 Shared Memory 缓存**：将 Global Memory 数据先加载到 Shared Memory，再从 Shared Memory 加载到 fragment，减少全局内存访问
2. **增大分块尺寸**：每个 Thread Block 处理更大的输出分块，提高数据复用率
3. **流水线预取**：在计算当前分块时，异步加载下一个分块的数据
4. **多 Warp 协作**：一个 Block 内多个 Warp 分工处理不同的输出分块

## 📝 总结

Tensor Core 是 GPU 上矩阵运算的硬件加速器，WMMA API 是使用它的入门级编程接口。核心要点：

1. Tensor Core 以小矩阵乘加为基本操作，吞吐量远超 CUDA Core
2. WMMA 以 Warp 为粒度，通过 fragment 抽象隐藏了数据在线程间的分布细节
3. 编程流程为 load → mma → store 三步，关键是正确处理布局和 leading dimension
4. WMMA 适合学习原理和自定义融合 Kernel，生产环境的标准 GEMM 优先用 cuBLAS/CUTLASS

如果你已经掌握了 WMMA，下一步可以学习 PTX 级别的 `mma` 指令（更灵活的分块控制）和 Hopper 架构的 WGMMA 指令（Warpgroup 级别的更大分块运算）。
